# Lean 4 Environment Explainer

Welcome to the Lean ecosystem! Because Lean is both a functional programming language and a theorem prover, its environment setup is slightly different from standard languages like Python or JavaScript. 

This document explains what each part of the Lean environment does so you understand exactly what we are installing and why.

## 1. Is Lean 4 the latest stable version?
**Yes.** Lean 4 is the current, actively developed, and standard version of Lean. 
Lean 3 was retired a while ago, and the massive mathematics library (`mathlib`) has been fully ported to Lean 4. All new development and learning happens in Lean 4.

## 2. The Core Components

When we install Lean, we are actually installing a toolchain managed by a few different pieces of software.

### `elan` (The Version Manager)
Think of `elan` like `nvm` for Node.js, `pyenv` for Python, or `rustup` for Rust. 
Lean undergoes rapid development, and different projects might require different specific versions of the Lean compiler. `elan` automatically downloads and manages these different versions in the background so you don't have to worry about them.

### `lean` (The Compiler and Theorem Prover)
This is the core engine. It parses your code, checks your proofs for logical correctness, and compiles your Lean code into executable binaries (typically via C).

### `lake` (The Package Manager and Build System)
Think of `lake` like `npm` for Node.js or `pip` + `setuptools` for Python. 
When you create a Lean project, you use `lake`. It downloads libraries (like `mathlib`) and builds your project. 

## 3. How Dependencies Work (No `requirements.txt`)
In Python, you use a `requirements.txt` file to list dependencies. **Lean does not use `requirements.txt`.**

Instead, Lean uses a file called `lakefile.lean` (or sometimes `lakefile.toml`). This file is automatically generated when we run `lake init`. Inside `lakefile.lean`, we tell `lake` which libraries we want to import. `lake` will then fetch those libraries from GitHub automatically when we build the project.

## 4. The IDE Setup (VS Code)
While you can write Lean in any text editor, it is **highly recommended** to use VS Code with the official **Lean 4 extension**. 
Theorem proving is highly interactive. As you write a proof, the VS Code extension communicates with the Lean compiler in real-time to show you the "Proof State" (what you have assumed, and what you still need to prove) in a panel next to your code.

## Summary of the Setup Flow
1. We run the `elan-init` script. This installs `elan`, `lean`, and `lake`.
2. We run `lake init LeanLearning`. This creates your project folder and the `lakefile.lean`.
3. You open the folder in VS Code, and the Lean extension takes over, providing you with real-time feedback as you write your modules!
